# 🌡️ Управление теплым полом (Стас) — ESP32-C3 SuperMini

Микроконтроллерная система раздельного управления двухзонным теплым полом и мониторинга температуры комнатного воздуха на базе **ESP32-C3 SuperMini** с локальным веб-интерфейсом, дисплеем TM1637, облачной интеграцией по MQTT (WQTT) и мобильным Android-приложением.

---

## 📌 Архитектура проекта и стандарт `PROJECT_STANDARDS.md`

1. **Единый заголовочный файл `src/global.h`:**
   - Все настройки по умолчанию (`DEFAULT_WIFI_...`, `DEFAULT_AP_...`, `DEFAULT_MQTT_...`), пины, структуры данных и прототипы модулей собраны исключительно в `global.h`.
   - Вспомогательные `.h` файлы модулей устранены; проект состоит только из `global.h`, `version.h` и исполняемых `.cpp` файлов.
2. **Безопасный старт и индикация `boot`:**
   - При подаче питания дисплей TM1637 инициализируется **ДО** `delay(5000)` и зажигает слово `boot` на время паузы ожидания USB CDC монитора.
3. **Неблокирующая логика:**
   - Внутри `loop()` и модулей категорически запрещены `delay()`; все тайминги и антидребезг кнопок построены на `millis()`.
4. **Версионирование:**
   - Автоматический инкремент патч-версии в `src/version.h` скриптом `generate_version.py` при каждой сборке.
5. **Сохранение в NVS Preferences:**
   - Уставки температур, состояние питания и сетевые настройки сохраняются с защитной паузой 2.5 сек (минимизация циклов записи Flash).
   - Изменение уставок применяется **мгновенно на лету без перезагрузки платы**.

## 🔌 Аппаратная конфигурация пинов (ESP32-C3 SuperMini)

| Пин | Назначение | Режим / Подключение | Описание |
|---|---|---|---|
| **GPIO 0** | TM1637 **CLK** | Выход | Тактирование 4-разрядного дисплея |
| **GPIO 1** | TM1637 **DIO** | Двунаправленный | Данные дисплея TM1637 |
| **GPIO 2** | Кнопка **MODE / SET** | `INPUT_PULLUP` (к GND) | Переключение режимов / шаг меню |
| **GPIO 3** | Кнопка **DOWN / -** | `INPUT_PULLUP` (к GND) | Короткое: `-0.5°C`. **Долгое (>0.8с): ВЫКЛ отопление** |
| **GPIO 4** | 1-Wire **DS18B20** | Подтяжка 4.7 кОм к 3.3V | Общая шина для 3 датчиков температуры |
| **GPIO 5** | Реле SSR **Зона 1** | Выход (Active HIGH) | Твердотельное реле теплого пола 1 |
| **GPIO 6** | Реле SSR **Зона 2** | Выход (Active HIGH) | Твердотельное реле теплого пола 2 |
| **GPIO 7** | Кнопка **UP / +** | `INPUT_PULLUP` (к GND) | Короткое: `+0.5°C`. **Долгое (>0.8с): ВКЛ отопление** |
| **GPIO 8** | Системный LED | Выход (Active LOW) | Встроенный синий светодиод активности |

## 📟 Особенности дисплея TM1637 (часовой тип с двоеточием)

У используемого модуля отсутствует точка `.` на каждом разряде, а распаяно центральное двоеточие `:`.
- **Формат отображения температуры:** `[Ц1][Ц2]:[Ц3][°]` (например, `25:5°` для 25.5°C). Центральное двоеточие служит десятичным разделителем, 4-й разряд выводит символ градуса `°` (`0x63`).
- **Авторотация экранов (каждые 2.8 сек):**
  1. Зона 1: заголовок ` 1  ` (0.75с) ➔ температура `25:5°` (2с)
  2. Зона 2: заголовок ` 2  ` (0.75с) ➔ температура `24:8°` (2с)
  3. Воздух: заголовок `Air ` (0.75с) ➔ комнатная температура `22:1°` (2с)
- **Сервисные сообщения:** `boot` (старт), `SAVE` (сохранение), ` On ` (включение), ` OFF` (выключение).

## 🎯 Алгоритм термостата: две уставки (пол и воздух)

- **Общая уставка пола (`targetFloorTemp`):** одна для Зоны 1 и Зоны 2 (по умолчанию `25.0°C`).
- **Уставка комнатного воздуха (`targetAirTemp`):** по умолчанию `22.0°C`.
- **Гистерезис:** фиксированный `0.5°C`.
- **Приоритет («Что первое нагрелось — то и отключает»):**
  1. **По воздуху:** как только воздух прогрелся до уставки (`T >= targetAir`), **немедленно отключаются ОБА пола** (даже если они еще не достигли своей температуры). Повторное разрешение на нагрев выдается только после остывания воздуха на `0.5°C` ниже уставки.
  2. **По полу:** если воздух еще требует тепла, каждая зона пола греет до достижения общей уставки пола. При перегреве отключается именно та зона, которая нагрелась.
  3. **Единый выключатель питания (`heatingEnabled`):** помещение одно, поэтому отопление включается и выключается централизованно (кнопками на плате, через Web UI, MQTT или мобильное приложение).

## 📡 Интеграция по MQTT (WQTT / Home Assistant)

Префикс по умолчанию: `warmfloor` (сервер: `wqtt.ru` / `dash.wqtt.ru`).

### Телеметрия (retained = true):
- **`warmfloor/status`:** `online` при подключении, `offline` по LWT (Last Will) и при корректной перезагрузке.
- **`warmfloor/state`:** единый краткий JSON пакет (каждые 5 сек и мгновенно при любых изменениях):
  ```json
  {
    "fl_set": 25.0,
    "ar_set": 22.0,
    "z1_t": 23.7,
    "z1_h": 1,
    "z2_t": 23.1,
    "z2_h": 1,
    "air": 21.5,
    "ar_dem": 1,
    "heat": 1
  }
  ```

### Топики команд:
- `warmfloor/floor/set_target` — уставка пола (например, `25.5`)
- `warmfloor/air/set_target` — уставка воздуха (например, `22.0`)
- `warmfloor/power` — включение/выключение питания (`1` / `0` или `ON` / `OFF`)
- `warmfloor/set` — прием единого JSON пакета настроек (`{"floor_set":26.0,"air_set":22.5,"heat":1}`)

## 📱 Мобильное приложение Android (`android_app/`)

- Полноценный проект Android Studio (Kotlin + Paho MQTT v3).
- **Автоматическая облачная сборка через GitHub Actions:** при каждом `git push` сервер GitHub автоматически компилирует APK и выкладывает его в раздел **Actions ➔ Artifacts**.
- Экран настроек подключения к брокеру WQTT с сохранением в `SharedPreferences`.
- Карточки зон, индикация работы реле, главный выключатель и регулировка обеих уставок с шагом 0.5°C.

## 📋 План работ на завтра:

1. **Сканер шины 1-Wire:**
   - Добавление режима сканирования шины GPIO 4 с выводом полных 64-битных ROM-адресов каждого найденного физического датчика DS18B20 в Serial и веб-интерфейс.
2. **Привязка реальных датчиков:**
   - Сопоставление уникальных адресов датчиков:
     - Датчик стяжки пола Зоны 1
     - Датчик стяжки пола Зоны 2
     - Датчик воздуха в помещении
3. **Переключение с имитатора на физическое чтение:**
   - Активация реального опроса шины раз в 2 секунды.
   - Внедрение фильтра ошибок: фиксация аварии только при **5 подряд неудачных чтениях** (`MAX_SENSOR_ERRORS = 5`); при успешном чтении счетчик ошибок сбрасывается в 0.
